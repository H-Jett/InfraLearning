## Q1：/32 与 /16 的计算量差多少？把 /32 输入调到 448 就等价于 /16 吗？

**问题**：ViT-B/32 在 224² 下 49 个 patch，ViT-B/16 是 196 个，参数量几乎一样。
计算量差多少倍？为什么 /16 更强更贵？/32 @ 448²（也是 196 个 patch）等价于 /16 @ 224² 吗？

**答案**：

**计算量约 4 倍，不是 16 倍。** 按每层 MAC 数拆开（`N` = token 数，`d` = 768）：

| 项 | 公式 | N=50 (/32) | N=197 (/16) |
|----|------|-----------:|------------:|
| QKV + 输出投影 | `4·N·d²` | 1.18e8 | 4.64e8 |
| MLP（4d 中间层） | `8·N·d²` | 2.36e8 | 9.29e8 |
| 注意力打分 + 加权 | `2·N²·d` | 3.8e6 | 5.9e7 |
| 每层合计 | | ≈3.6e8 | ≈1.45e9 |
| **12 层合计** | | **≈4.3 GMAC** | **≈17.4 GMAC** |

比值 **≈4.05×**，和公开数字（ViT-B/32 ≈4.4 GFLOPs、ViT-B/16 ≈17.6 GFLOPs）一致。

**为什么不是 16 倍**：只有注意力打分那项是 `O(N²)`，而在 N=197 这种"短序列"下它只占**约 4%**；
真正的主体是 `O(N·d²)` 的投影和 MLP，对 token 数**线性**。
（推论：token 数还要再涨一个数量级——比如高分辨率 VLM 里几千个视觉 token——
二次项才会开始主导。这就是为什么 VLM 比 ViT 更怕 token 膨胀。）

**为什么 /16 更强**：patch 越小，**每个 token 覆盖的像素越少、位置越精确**，
小目标和细纹理不容易被"平均掉"。代价就是上面的 4 倍算力。

**/32 @ 448 不等价于 /16 @ 224**，尽管 token 数与 FLOPs 相当：

1. **压缩比不同**：/32 的 patch_embed 要把 `32×32×3 = 3072` 个数压成 768 维（4 倍有损压缩），
   /16 是 `16×16×3 = 768` → 768（几乎无压缩）。patch 内部的细节，/32 丢得更多。
2. **但看到的原始像素更多**：/32@448 的输入图是 448²（20 万像素），/16@224 只有 224²（5 万像素）。
   所以两者是"看得更多但每块更糊"vs"看得少但每块更清"，各有胜负，取决于任务。
3. **位置编码要插值 + 通常得再训**：/32 的位置表只有 49 个空间位置，插值到 196 会掉特征
   （本章实测 448² 时 cosine 0.914），不重训直接用会掉点。

**工程结论**：想提分辨率，业界更常见的是 **tiling / AnyRes**——把大图切成若干块 224 分别过视觉塔，
而不是把位置编码硬插值。这条路第 8 章讲。

## Q2：用平均池化替代 CLS token 会怎样？

**问题**：去掉 CLS，改用 49 个 patch token 的平均池化作图像表示，效果会怎样？CLS 的优势是什么？

**答案**：

先分两种情况，别混：

**情况一：拿现成的 CLIP 直接把 CLS 换成平均池化 → 会大幅掉点。**
因为 `visual_projection`（768→512 那层）和整个对比学习目标都是**针对 CLS 的输出分布**训练的。
平均池化出来的向量统计性质完全不同（均值、范数、方向分布都不一样），
喂给同一个投影层等于送了个 out-of-distribution 输入。这不能说明"平均池化不好"，只说明**不能混用**。

**情况二：从头训练时选平均池化 → 完全可行，效果接近。**
实际上主流模型三种池化都在用（本章表格）。差别是有的，但没有"谁碾压谁"：

- **CLS 的优势**：它是一个**可学习的 query**，可以在 12 层里反复决定"这次多读哪几块"，
  等价于一个**数据驱动的加权池化**。平均池化是**无参数、均匀权重**——
  一张图里 80% 是天空时，主体信息会被背景稀释。本章实测的 CLS 注意力最大/最小权重相差 **21 倍**，
  可见它确实在做强选择。
- **平均池化的优势**：无额外参数、不占序列位置、对"整体统计"类任务更稳，
  且不会出现 CLS 那种**少数 token 范数极高**的病态现象（*Vision Transformers Need Registers* 讨论的
  attention sink / 高范数 token 就与此有关）。
- **注意力池化**（SigLIP、CoCa）：本质是"把 CLS 的可学习 query 从序列里拿出来单独做一次
  cross-attention"，等于取两者之长——这也是现在更受青睐的做法。

**最该记住的一点**：这个问题在 **VLM 里基本不存在**。VLM 需要的是全部 patch token 送进 LLM，
池化方式只影响"视觉塔单独用作检索/分类"的场景。LLaVA 系代码里直接 `hidden_states[:, 1:]` 把 CLS 丢掉，
就是这个道理。

## Q3："底层局部、高层全局"哪里对、哪里错？

**问题**：第 0 层最全局的头距离已 3.82，最后一层最局部的头也有 3.37。
"ViT 像 CNN 一样底层看局部、高层看全局"这句话哪部分对、哪部分错？换 ViT-B/16 重做，哪个数字会变？

**答案**：

**对的部分**：**存在**"越深越全局"的趋势。最局部的头从 1.45（第 0 层）→ 3.37（第 11 层），
12 个头的跨度从 2.37 收缩到 0.26，层平均从中段的 1.95 单调爬到 3.49。
高层确实几乎全在做全局整合。

**错的部分（三处）**：

1. **底层不是"只能"局部**：第 0 层就有头的平均距离 3.82（7×7 网格最大距离 8.5），
   这是**接近全图**的关联。CNN 底层做不到——卷积的感受野被 kernel 尺寸**物理限制**；
   自注意力从第一层就有"看任意远"的能力。**ViT 的局部性是学出来的偏好，不是结构约束**，
   这是本质区别。
2. **层平均不单调**：第 0 层（2.89）比第 4 层（1.95）更"全局"。只看层平均会得出错误结论——
   它被少数全局头拉高了。**要按头看分布，不要只看均值。**
3. **"层级"是统计倾向，不是保证**：同一层里既有 0.60 的头也有 3.92 的头（第 7 层），
   说白了每层都在"局部+全局"混着干。

**换 ViT-B/16（14×14 网格）预期**：

- **绝对数值会整体上移**：网格变大，patch 间最大距离从 8.5 变成 18.4，
  同一个"看全图"的头测出来的距离数字会大得多。**跨模型比较必须先按网格尺度归一化**
  （比如除以最大距离），否则纯属比较尺子。
- **层间跨度会变大**：更细的网格给了"真正局部"更大的空间（/32 里一个 patch 就是 32 像素，
  想局部也局部不了多少）。所以预期底层会出现比 1.45（归一化后）更明显的局部头。
- **趋势应保持一致**：归一化后仍是"底层分布宽、高层收窄上移"——这与 ViT 论文 Fig. 7
  在 B/16 上的结果吻合。

但注意：以上是**预测**，不是结论。要下判断就按本章练习 C 的方法在目标模型上量一遍——
这也是本书的做法。

## Q4：为什么"错的位置信息"比"没有位置信息"更能骗到模型？

**问题**：位置编码置零 → 概率接近均匀（0.28/0.30/0.33/0.10）；打乱 → 0.71 的高置信度错误答案。
为什么？翻译成一条该警惕的 bug 模式。

**答案**：

**置零 = 信息缺失，模型"知道"自己瞎了。**
所有 patch 共享同一个位置向量（全零），空间结构彻底消失，模型看到的是一袋无序碎片。
它只能靠纹理/颜色统计瞎猜，各类得分被拉平 → **低置信度、接近均匀分布**。
这种失败**看起来就像失败**，容易被发现。

**打乱 = 信息错误，模型"以为"自己看得很清楚。**
每个 patch 仍然拿到一个**训练时见过的、合法的**位置向量，
输入分布还在模型熟悉的流形上，注意力照常按"空间邻近"的先验去整合——
只是那些"邻近关系"全是错的。于是模型完成了一次结构完整、内容错乱的推理：
雪地与树干的纹理证据被拼成了"雪林"，还给出 **0.71** 的高置信度。
这种失败**看起来像成功**。

**要警惕的 bug 模式**：

> **在多模态管线里，"结构完整但内容错位"的输入不会报错，只会让模型自信地答错。**

高发场景（都是真实踩过的）：

- **patch / token 顺序错**：手写 reshape 时把 `(H, W)` 写成 `(W, H)`，图像被隐式转置；
- **多图请求配错**：N 张图的视觉 token 与文本里的 `<image>` 占位符**顺序对不上**；
- **图文错配**：数据管线里 shuffle 之后 image 和 caption 的索引错开一位；
- **视频帧乱序**：帧采样后没保序，时间关系全错；
- **位置编码插值实现错**：把 `[1+N, d]` 的表连 CLS 一起插值。

这些都**不会抛异常**，loss 也可能只是略高——如果你只看"跑通了 / loss 在降"，会一路错到评测。

**防御手段**：

1. **golden 回归测试**：固定几个输入（含一张固定图），把模型输出/中间特征的哈希或数值存下来，
   任何改动后必须能复现——本章练习 D 的"④ 恢复原始（自检）"就是这个思路的最小版；
2. **抽检可视化**：把预处理后的图、token 顺序、图文配对**画出来看一眼**，别只信代码；
3. **故意破坏做对照**：像本章这样主动打乱一次，确认"破坏了指标真的会掉"——
   如果打乱之后指标不掉，说明你的评测根本没在测这个能力。
