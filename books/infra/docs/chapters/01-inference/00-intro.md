# 第一部分 · 推理与服务

> 本部分导读。

## 这一部分讲什么

大模型训练完之后，要能对外**服务**——把 prompt 变成回答。这一部分带你搞清楚：一个推理请求在
GPU 上到底怎么跑、慢在哪、业界用哪些技术把它做快做省，最后落到真实引擎（vLLM / SGLang /
TensorRT-LLM）。

## 为什么从推理开始（而不是训练）

因为推理是理解 GPU infra 最**直观**的入口：一个请求进、一串 token 出，瓶颈清晰、反馈立竿见影。
而且这里建立的核心直觉——**memory-bound vs compute-bound、显存怎么算、瓶颈怎么找**——会**整套迁移**
到后面的训练工程（第五部分）。先在推理这条短链路上把思维方式练熟，再去啃训练。

## 主线（一句话）

> LLM 推理 = 一次"吃满算力"的 **prefill** + 一长串"喂不饱算力"的 **decode**（memory-bound）。
> 几乎所有优化，都是在跟 decode 的 memory-bound 特性、以及它带来的 KV cache 显存压力作斗争。
