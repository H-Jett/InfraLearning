# 第 4 章 · 思考题参考答案

> 只记录问题与参考答案。对应正文《第 4 章 4.7 思考题》。

## 1. ~1% 利用率的浪费来自哪？PagedAttention 怎么消除？

**参考答案**：两类浪费都有，但朴素法这里主要是**预留过度**：

- **预留过度（可归为内部碎片）**：给每条序列按"最大长度 40960"预留连续显存，实际平均只用几百 token，
  预留的绝大部分闲置——这是 1% 利用率的主因。
  → PagedAttention 用**按需分配 block** 消除：序列写多少才给多少块。
- **外部碎片**：变长序列不断分配 / 释放，连续显存被切出一堆放不下新序列的小空洞。
  → PagedAttention 用**固定大小的 block + 物理块可不连续** 消除：任何空闲块都能被任何序列使用。

**残余浪费**：只剩每条序列**最后一个 block** 没填满的部分（内部碎片，≤ block-1 个 token），很小。

## 2. block 大小怎么选，有什么权衡？

**参考答案**：

- **block 越大**：每条序列最后一块的**内部碎片越多**（最多浪费 block-1 个 token 的空间）；
  但 block table 更短、管理/寻址开销小，kernel 一次处理连续一大块也更高效。
- **block 越小**：内部碎片越少、显存更省；但 block 数量多 → block table 变大、分配/查表的管理开销上升，
  kernel 访问更零碎。

所以是"碎片 vs 管理开销/kernel 效率"的权衡，vLLM 默认 16 是个经验上的折中。

## 3. 共用长 system prompt 时，PagedAttention 为什么能省显存和算力？

**参考答案**：多个请求若共享同一段 system prompt，这段的 K/V 是完全一样的。PagedAttention 里
这段对应的**物理 block 只存一份**，多条序列的 block table 都指向它（配合写时复制）——

- **省显存**：相同前缀的 KV 不重复存 N 份；
- **省算力**：这段前缀的 prefill 只需算一次，后续请求直接复用，不必重算。

而**朴素连续预留**做不到：每条序列各占一块独立的连续显存，物理上无法让两条序列指向同一份数据，
只能各存各的、各算各的。这正是第 5 章前缀复用 (Prefix Caching) 的基础。
