# 第 2 章 · 思考题参考答案

> 只记录问题与参考答案。对应正文《第 2 章 2.8 思考题》。

<a id="q1"></a>

## 1. batch=32、seq_len=8192 时，Qwen3-0.6B 的 KV cache 多大？

**参考答案**：用公式 `2 × 层数 × KV头 × head_dim × seq_len × batch × 字节`：

```
2 × 28 × 8 × 128 × 8192 × 32 × 2 字节 = 30,064,771,072 字节 ≈ 28.0 GiB
```

或者用"每 token 112 KiB"快算：112 KiB × 8192 × 32 ≈ 28 GiB。

模型权重才 1.11 GiB → KV cache 是权重的 **约 25 倍**。一张 32 GiB 的卡，**光放这份 KV cache
（28 GiB）就快满了**，再加上模型权重和激活基本会 OOM。这直观说明：真正吃显存的往往不是模型，
是 KV cache，且被 batch 和 seq_len 双重放大。

<a id="q2"></a>

## 2. 为什么缓存 K 和 V，而不是 Q，也不是注意力输出？

**参考答案**：看注意力公式 `out_t = softmax(Q_t · K_{1..t}ᵀ/√d) · V_{1..t}`：

- 过去每个 token 的 **K、V 会被后续每一步反复读取**（新 token 都要和所有历史 K 打分、对所有历史 V 加权），
  所以缓存它们能免去重算。
- **Q 只在自己那一步用一次**，之后再不用，缓存无意义。
- **注意力输出**也不会被后续步骤复用（每步重新算），缓存无意义。

<a id="q3"></a>

## 3. GQA 把 KV 头从 16 减到 8，KV cache 减半，为什么质量不会减半？

**参考答案**：GQA 减的是 **KV 头**，**16 个 Query 头一个没少**——模型仍有 16 路独立的 Query
去从不同角度"提问"。只是每 2 个 Q 头共享同一组 K/V 来"作答"。表达能力主要由 Q 头的数量和多样性
支撑，共享 KV 带来的信息损失有限，所以在大量实验中质量几乎不降，却把 KV cache（以及解码时读取 KV
的带宽）显著减小。MQA（所有 Q 头共享 1 组 KV）更省，但共享过度，质量影响比 GQA 明显。
