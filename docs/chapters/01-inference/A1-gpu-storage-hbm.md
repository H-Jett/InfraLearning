# 补充 A 　GPU 的存储层级与 HBM

> 本节是第 1 章"访存受限 (memory-bound)"结论的硬件背景：搞清楚"从显存搬权重"
> 这句话里，权重到底存在哪、经过哪几级、为什么"搬"是瓶颈。
> 内容讲通用原理，不绑定具体机型。

## A.1 为什么要讲存储

第 1 章的核心结论是：解码阶段每生成一个 token，都要把整个模型的权重从显存读一遍，
瓶颈在"搬"而不是"算"。要真正理解这句话，得知道 GPU 里数据是怎么分级存放、怎么流动的。

## A.2 存储层级：从"大而慢"到"小而快"

GPU 的存储不是一块，而是一个**层级 (memory hierarchy)**[^hier]：

```
显存 HBM / GDDR（几十 GB，带宽 TB/s 级）   ← 权重、KV cache、激活都住这儿。大，但"远"
      │  搬运（瓶颈就在这一跳）
      ▼
L2 缓存（几十 MB）
      ▼
每个 SM 的 shared memory / L1（几百 KB）、寄存器   ← 极快（几十 TB/s），但极小
      ▼
计算单元（CUDA cores / Tensor cores）   ← 真正做乘加的地方
```

要点：

- 计算单元只能吃**寄存器**里的数据。
- 模型权重动辄几个 GB，片上那点内存（几十 MB）根本装不下，所以权重**只能常驻显存**，
  每次要算都得从显存流经这条链路搬上来。
- **瓶颈精确地在 `显存 → 片上` 这一跳**：这条链路里显存带宽最低，而要搬的权重又最大。

所以第 1 章说的 "memory-bound"[^mb]，更准确的名字是 **显存带宽受限**。

## A.3 HBM 是什么

<a id="hbm-3d"></a>
现代数据中心 GPU 的显存多用 **HBM (High Bandwidth Memory，高带宽内存)**[^hbm]。它和传统的
**GDDR**[^gddr] 显存最大的区别是封装方式：

- **GDDR**：显存颗粒像平房一样平铺在电路板上，离 GPU 有一段距离。
- **HBM**：把多层 DRAM 芯片像盖楼一样**垂直堆叠**，用**硅通孔 (TSV)**[^tsv] 做层间连接，
  再通过**中介层 (Interposer)**[^interposer] 直接贴在 GPU 芯片旁边。

HBM 的两个真正优势：

1. **超宽位宽 → 巨大带宽**：每个 HBM 堆栈的接口宽达 1024 位（相比之下单颗 GDDR 芯片只有 32 位），
   多个堆栈并联，带宽轻松做到 GDDR 的数倍。
2. **每比特能耗低、封装紧凑**：走线短、并行宽，单位数据传输更省电，也更省空间。

> **注（一个常见误区）**：HBM 的杀手锏是**带宽和能效，不是低延迟**。它的单次访问延迟和 GDDR
> 其实差不多——延迟主要由 DRAM 存储单元本身决定，不是靠"走线短"能显著降低的。所以记住：
> HBM 赢在"每秒能搬多少"，不是"搬一次多快到"。

## A.4 HBM vs GDDR：原理不变，只是墙的高矮不同

"大模型推理受限于显存带宽"这个**原理，和用哪种显存无关**。区别只是带宽墙砌得多高：

- 消费级 GPU 多用 GDDR，带宽较低，墙较矮；
- 数据中心 GPU 用 HBM，带宽高出数倍，墙砌得更高，能扛更大的模型、更高的并发。

换句话说，HBM 不是"改变了游戏规则"，而是"把同一堵墙往上垒"——让你在撞墙前能跑得更远。

## A.5 回到推理：带宽如何决定 TPOT

把 A.2 的结论量化，就得到第 1 章那个能记一辈子的估算（TPOT[^tpot] 指每 token 输出耗时）：

> **TPOT 的理论下限 ≈ 模型权重大小（字节） ÷ 显存带宽（字节/秒）**

因为每生成一个 token 至少要把全部权重从显存读一遍，这个"读一遍"的时间就是不可逾越的地板。
举例（数量级感受，非某台机器实测）：

- 一个 70B 模型用 fp16 存 ≈ 140 GB；若显存带宽 ≈ 2 TB/s，则 TPOT 下限 ≈ 70 ms/token。
  算力再强也突破不了这个地板。
- 想突破？只能**减少要搬的字节**——这正是**量化**（fp16 → int8/int4，见后续章节）的根本动机：
  权重更小 → 每 token 要搬的更少 → 墙更矮。

这条把"硬件（带宽）—软件（量化）—指标（TPOT）"三者串成了一条因果链，是推理优化的主线之一。
